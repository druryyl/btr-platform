# Investigation: Intake Retur Sync Flow (Warehouse → Main Office)

**Date:** 2026-11-09  
**Investigator:** AI Agent  
**Scope:** How Intake Retur data entered at warehouse (j09) reaches main office (j05)

---

## Executive Summary

**The flow is already implemented and working.** Intake Retur data travels:

```
Warehouse (j09) → Cloud API (j06) → Main Office Sync (j07) → Main Office DB (j05)
```

The user didn't see it in j07's UI because:
1. It's gated by a **registry flag** (`DownloadReturnOrder = 1`)
2. It runs **automatically every 5 minutes** (no manual button visible)
3. The UI button label is generic ("Quick Download" / "Extended Download") and not obviously Return-Order-specific

---

## Detailed Flow

### 1. Warehouse Entry (j09-btr-retur-gudang / BtrReturGudang.Wpf)

**Input:** Operator scans/enters return items at warehouse → saved as local Draft.

**Upload to Cloud:** Two paths:
- **Immediate (F10 Save & Upload):** `MainViewModel.ExecuteSaveAndUpload()` → `ReturnOrderListViewModel.UploadOrderAsync()` → `ISyncService.TriggerDocumentUploadAsync()` → `BtradeApiClient.UploadReturnOrderAsync()` → `POST api/return-order`
- **Background (5-min timer):** `MainViewModel.ExecuteBackgroundSyncPassAsync()` → `SyncService.RunFullSyncPassAsync()` → pushes all pending Draft orders via same API

**API Client:** `BtradeApiClient` attaches headers:
- `X-Session-Location` = WarehouseCode (e.g., `GAMPING`)
- `X-Session-Actor` = Operator Google email

**Cloud Endpoint:** `POST api/return-order` (ReturnOrderController.Submit)

---

### 2. Cloud Relay (j06-pkl-btrade-api / btrade.webapi)

**Controller:** `ReturnOrderController.Submit()` (lines 26-56)

**Processing:**
1. Resolves `ServerId` from `X-Session-Location` header (warehouse → server mapping)
2. Resolves `SubmittedBy` (BTR UserId) from `X-Session-Actor` header (operator email → identity)
3. Sends `ReturnOrderUploadCommand` via MediatR to application layer

**Persistence:** Cloud stores in `BTRADE_ReturnOrder` and `BTRADE_ReturnOrderItem` tables (confirmed by user)

**Download Endpoint:** `GET api/ReturnOrder/incremental/{tgl1}/{tgl2}/{serverId}` (ReturnOrderController.IncrementalDownload)
- Returns all Return Orders for that server/date range
- **Includes `SubmittedBy`** (operator UserId) for audit trail (TD-15)

---

### 3. Main Office Sync (j07-btrade-sync)

**Entry Point:** `SyncForm.ProcessReturnOrder()` (lines 296-382)

**Triggered by:**
- Automatic 5-min timer (`ProcessingTimer_Elapsed` → `ProcessReturnOrder(RANGE_PERIODE)`)
- Manual "Quick (H-3)" / "Extended (H-6)" context menu on IncrementalDownloadOrderButton

**Gating Flag:** Registry `DownloadReturnOrder` must = `"1"` (configurable in KonfigurasiForm → "Download Return Order" checkbox)

**Flow inside ProcessReturnOrder:**
1. **Driver projection upload** (refreshes Driver cache)
2. **Download** via `ReturnOrderIncrementalDownloadService.Execute(periode)` → calls Cloud `GET incremental` endpoint
3. **Stage** each order: `ReturnOrderDal.Insert()` / `Update()` into Main Office `BTR_ReturnOrder` table
   - Status = `"Synced"` (staged, not yet imported)
   - `CreatedBy` = Cloud-resolved `SubmittedBy` (operator UserId) or fallback sync account
   - `ReturnOrderNo` left empty (numbering is office-side only)
4. **Import** each order: `MainOfficeCommandExecutor.ImportReturnOrder()` → `ImportReturnOrderCommand` via MediatR
   - This is the **authoritative import** with numbering (`ReturnOrderNo`) and validation
   - Runs in-process using j05's application/infrastructure (IR-08 pattern)

**Repository:** `ReturnOrderDal` / `ReturnOrderItemDal` target Main Office SQL (connection from j07's app.config)

---

### 4. Main Office Database (j05-btr-distrib)

**Tables populated:**
- `BTR_ReturnOrder` (header)
- `BTR_ReturnOrderItem` (lines)

**Numbering:** `ReturnOrderNo` generated by `ImportReturnOrderCommand` → `ReturnOrderBuilder` → `NunaCounter` (office-owned, ADR-RO-002/008)

**Audit:** `CreatedBy` = warehouse operator UserId (relayed via Cloud `SubmittedBy`)

---

## Why User Didn't See It

| Reason | Detail |
|--------|--------|
| **No dedicated UI button** | Return Order sync runs under generic "Quick Download" / "Extended Download" context menu items |
| **Registry flag off by default** | `DownloadReturnOrder` must be enabled in KonfigurasiForm (checkbox "Download Return Order") |
| **Auto-run only** | 5-min timer runs silently; log shows "Starting return-order processing cycle..." but no prominent button |
| **Log-only visibility** | Success/failure appears in LogTextBox, not a grid or dashboard |

## Verification Steps

1. **Check registry on Main Office machine:**
   ```
   HKEY_CURRENT_USER\Software\BTradeSync\DownloadReturnOrder = "1"
   ```

2. **Check SyncForm log** after waiting 5 minutes or clicking "Quick (H-3)":
   - Should see: "Starting return-order processing cycle..."
   - Then: "Staged return order {CustomerName} ..." / "Imported return order {ReturnOrderNo} ..."

3. **Verify in Main Office DB:**
   ```sql
   SELECT * FROM BTR_ReturnOrder WHERE Status = 'Synced' ORDER BY ReturnOrderDate DESC;
   ```

4. **Check Cloud has data:**
   ```sql
   SELECT * FROM BTRADE_ReturnOrder ORDER BY ReturnOrderDate DESC;
   ```
